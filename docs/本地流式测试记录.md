## 实际网络回放

使用同 Android 的 POST 会话 + JTR1 PCM 帧 + WebSocket 字幕协议，服务器未注入假识别或翻译返回值。公开 Common Voice 日语 WAV 按真实播放速度上传，报告保存实际识别和译文，供人工复核。

| 报告 | 实现与用途 |
| --- | --- |
| `evaluation/results/streaming-local.json` | 首轮接通：10 段语音，61.48 秒含间隔；有未经确认的临时输出 |
| `evaluation/results/streaming-local-stable-preroll200.json` | 临时识别需要两次共同前缀，200 ms 前导音频；10 段 |
| `evaluation/results/streaming-local-preroll400-early-frame.json` | 400 ms 前导音频，两轮重复，共 20 段；发送帧的时机偏早约 100 ms，仅保留为开发对照 |
| `evaluation/results/streaming-local-stable.json` | 当前最终检查：完整帧采集结束后才发送，400 ms 前导音频，两次共同前缀确认 |

前三份开发对照按帧开始时间发送完整帧，相比真实采集最多提前约 100 ms，不应直接用于当前版本延迟结论。最终报告已修正采集帧可用时机，并记录参数和模型清单。

最终报告的实际测量摘要在下方归档；“音频结束点”是字幕事件的 `end_audio_ms`，已包含 VAD 等待的静音。它不是人工标注的说话终点。播放文件可能含有尾部静音，因此字幕早于文件结束不代表系统预测了未来。

| 检查项 | 实际结果 |

| 连续上传音频 | 122.56 秒，含片段间隔；10 段公开音频重复两轮 |

这些延迟仅包含本机实时帧上传和服务推理，不含 Android 采集、USB 真机往返、字幕绘制或人工标注的实际说话终点；不应简写成“手机总延迟 0.6 秒”。

## 已发现的质量问题

流式断句和临时字幕确认可以减轻过早乱猜，但未消除识别或翻译错误。例如早期临时识别 `ちむらさわわ` 被翻成了“小丑的粪便”，因此改为相邻两次识别确认前缀后才送临时字幕。VAD 词首保留从 200 ms 增至 400 ms，以减少较弱词首被截掉的风险。

已知整句 `写真` 仍可能被识别成 `シャンシン` 并进一步译成“香欣”；`解毒剤` 也有错误。系统不会用固定演示内容替换这些真实错误。重复测试同一组公开样本只是功能和稳定性检查，不是新的准确率验证集。
