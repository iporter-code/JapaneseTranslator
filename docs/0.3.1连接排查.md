# 0.3.1 连接修复与排查

用户反馈手机 App 无法连接。电脑端已使用当前运行中的公网地址，验证 HTTPS `/health`、应用令牌创建会话、WSS `stream.ready`、应用层 `ping/pong`，均成功。检查结果见 `evaluation/results/connection-check.json`，没有写入令牌。没有重启模型或更换地址。

这不能证明手机的网络可达，也不能据此认定手机端失败的具体原因；需要手机本身的错误信息。

## 本次代码改动

- 发现创建会话后读取响应正文发生在调用方协程上下文，当前调用方为主线程；慢网络需要继续读 socket 时可能触发主线程网络异常。现将响应正文读取和关闭移至 `Dispatchers.IO`。没有收到手机的实际异常，因此不将此标为已确认的唯一原因。
- 主界面新增“测试后端连接”：依次检查 HTTPS 健康接口、访问令牌/字幕连接、WebSocket 心跳，无需先申请采音授权。
- 域名解析、TLS/证书、超时、端口拒绝、HTTP 握手错误分别显示；错误提示不输出访问令牌或底层异常正文。
- 地址保存时去除两端空白并显示具体配置错误，测试时自动保存当前地址和新填入的令牌。
- 测试期间禁用启动采音和修改地址，避免诊断会话与实际采音争抢唯一模型会话。
- 没有关闭证书校验，没有改用 HTTP，也没有改变手机无需额外软件的使用方式。

## 手机执行

1. 覆盖安装 `artifacts/日语实时字幕-0.3.1.apk`，原有设置与令牌保留。
2. 选择“连接翻译服务”。后端地址只填电脑当前的 `https://域名`，不要附加 `/health` 或接口路径。
3. 点击“测试后端连接”。如果令牌输入框留空，会使用之前保存在设备上的令牌。
4. 提示“连接通过”后点击“授权并开始”。
5. 若失败，请提供显示的具体错误文字，并用同一手机浏览器打开相同域名的 `/health` 作为对照。

浏览器也打不开时，应先排查手机到临时通道的网络可达性。浏览器能打开但 App 测试失败时，再依据证书、令牌或 WebSocket 阶段继续定位。不能仅凭电脑测通就把问题归结为用户输入错误。

APK 版本码 4；本次 Android 构建、9 项核心测试与 Lint 检查通过，Lint 0 错误、6 警告。新增的错误归类覆盖 DNS、证书和超时提示。新版本尚未在用户手机上运行，不能标为连接问题已完成真机验收。
