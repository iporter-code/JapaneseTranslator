# 0.3 更新与真机复测

针对用户提供的华为截图及 8 项反馈进行修改。新 APK 为 `artifacts/日语实时字幕-0.3.0.apk`，版本码 3，沿用调试签名，可覆盖安装 0.2 并保留地址、访问令牌和样式设置。

## 后台问题的边界

旧版因持续断网或服务繁忙而主动停止，与系统强制杀进程的表象相似。这次分别处理：可恢复网络问题继续重连；不可恢复的权限、授权或认证问题仍会明确结束，并保留停止原因。

唤醒锁解决 CPU 休眠造成的中断，不能保证华为系统永不清理进程。仍应在本机操作：

1. 打开 App 的“后台运行保护”区域，进入华为启动管理。
2. 找到“日语实时字幕”，关闭自动管理，允许后台活动。
3. 在最近任务中锁定本应用，并允许前台运行通知。
4. 如系统仍限制，检查电池优化中是否对本应用启用了严格限制。
5. 系统停止捕获或进程被强杀后，重新打开 App 并点击开始，重新完成系统授权；不承诺偷偷恢复捕获。

参考：[华为官方后台运行排查](https://consumer.huawei.com/cn/support/content/zh-cn00428704/)、[Android 进程生命周期](https://developer.android.com/guide/components/activities/process-lifecycle)。这些操作仍需在用户的 Mate 40 Pro / 鸿蒙 4.2 上验证，未宣称已经解决所有厂商清理行为。

## 提速与语气词的实际限制

上述等待时间和过滤规则已经修改并自动测试；公网线路、语音本身、模型误识别仍会影响最终速度和质量。本机回放延迟不能当作手机总延迟。无损压缩只减小应用协议包，不降低音频质量，其数字不含 WebSocket 自身压缩和 TLS 开销。

短语音门槛测试使用注入的语音概率验证 128 ms 片段不被代码丢弃，语气词映射测试使用日文文本；它们不等于真实电影语气词识别率。尚无用户所指片段用于声学验证。没有明确语言内容的呼吸、呻吟或背景音可能仍不被 Whisper 当作对白，不能保证所有“嗯、啊”都能正确识别或根据情境准确译出。

- Android 8 项测试通过，新增“空启动”“等待新句时保留旧译文”“无损压缩包”覆盖；构建成功。

- 0.3 首轮公网回放：20.584 秒含间隔音频，3 段均收到最终字幕，最终返回滞后约 0.917～1.075 秒；原生识别耗时约 302～314 ms，服务端输入积压约 765～782 ms。见 `evaluation/results/streaming-internet-v030.json`。不同临时通道的路由不同，不把与旧通道的差异全部归因于代码，也不当作手机实测。

- 新增公网后台启动与安全停止脚本，避免为了保留服务必须一直打开启动终端。

## 手机上复测

1. 覆盖安装 0.3，不必先卸载，以保留自己的访问令牌。
2. 使用电脑后台服务新显示的 HTTPS 地址。临时地址更换后在 App 更新并保存。
3. 开始后不播放影片，确认没有“等待对白”，只有小“×”。
4. 播放一句日语，收到译文后暂停影片至少 15 秒，确认译文保持。
5. 恢复播放，在下一句识别过程中确认旧译文不会先消失。
6. 开关“显示原文（日语）”，将两种透明度分别调到 100% 验证；整层透明时仍能点“×”。
7. 将系统字体调大，检查横竖屏换行和关闭按钮没有重叠，拖动后位置可保留。
8. 完成后台保护设置，切换到夸克连续播放、返回桌面、再切回；若中断查看主界面停止原因和网络往返时间。
9. 在可复现的短对白中测试“嗯、啊、诶”，区分“未采到声音”“模型没识别”“识别后没翻译”。
10. 点击小“×”，确认悬浮窗与前台通知消失，音频不再上传。

## 电脑后台运行

```powershell
.\scripts\start-internet-backend.ps1 -Background
# 停止本项目创建的后台模型服务与通道：
.\scripts\stop-internet-backend.ps1
```

后台服务的输出保存在被 Git 忽略的 `.tools/internet-*.log`，不写音频或字幕正文。停止脚本通过本项目生成的信号文件请求正常退出，不按任意 PID 强杀进程。电脑仍需保持开机、不休眠并联网。
